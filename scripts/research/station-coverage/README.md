# R1 — 상류 관측소 커버리지 실측 (2026-09-04)

`docs/TODO.md` **R1** · valley-ds `open-questions.md` §A 의 "관측소가 계곡 상류에 있는가" 를 데이터로 판정한다.
수도권 계곡 후보 30개 × 관측소(한강홍수통제소 강우·수위, 기상청 AWS)를 **같은 중권역 ∧ 관측소 표고 ≥ 계곡 표고 ∧ 거리 ≤ 15 km(10 km 병기)** 로 매칭해
"상류 강우 관측소가 1개 이상인 계곡 비율" 을 구했다. 연구 스크립트이며 앱 코드가 아니다(biome/tsc/vitest 는 `scripts/research` 를 보지 않는다).

## 판정 요약

| 기준 | 커버리지 | valley-ds 판정 |
| --- | --- | --- |
| **15 km · HRFCO 강우 + AWS** | **12/30 = 40.0%** | 부분 노출(40~70%) — **경계값**, 계곡 1개 차이로 <40% |
| 15 km · HRFCO 강우만 | 8/30 = 26.7% | MVP-3 재설계(<40%) |
| 10 km · HRFCO + AWS | 8/30 = 26.7% | MVP-3 재설계 |
| 10 km · HRFCO 만 | 4/30 = 13.3% | MVP-3 재설계 |
| 15 km · 표고차 ≥ 50 m 까지 요구(평지 이웃 제외) | 9/30 = 30% | MVP-3 재설계 |
| 15 km · 같은 **표준유역**(sbsncd) 까지 요구 | 7/30 = 23.3% | MVP-3 재설계 |

**권고: MVP-3 "관측소 기반 상류 강우 경보" 는 재설계 대상이다.** 명목 수치는 경계(40.0%)지만,

1. 두 소스를 합쳐 가장 느슨한 기준에서만 40% 이고, 어느 한 조건을 조금만 조이면(10 km, HRFCO 만, 표고차 50 m, 표준유역) 전부 40% 아래다.
2. "커버됨" 12개 중 계곡 위쪽 산지에 진짜 관측소가 있는 경우는 **유명산·어비(중미산 HRFCO, +112/+250 m, 2 km)·광덕계곡(광덕산 AWS, +472 m, 2.7 km)·지장산(관인 AWS)** 정도다. 나머지는 표고차 1~30 m 의 읍내 관측소(용추 ↔ 화악교 +1 m 10.2 km, 함허동천 ↔ 양도 +2 m, 수동 ↔ 가평조종 +10 m)거나 13 km 밖 도심 관측소(우이동 ↔ 서울 중구 AWS)다.
3. 민감도 표가 원인을 말해 준다 — **표고 조건을 빼면 30/30(100%)**, 유역 조건을 빼면 19/30. 즉 관측소는 15 km 안에 얼마든지 있지만 전부 **계곡보다 낮은 읍내·하류**에 있다. 계곡 유역(산지 두부 유역)에 우량계가 없다는 valley-ds 의 우려가 사실이다.
4. 가평 북면 6개 계곡(명지·조무락·백둔·논남기·도마치·경반)은 상류 관측소 0 — 가장 가까운 고지 AWS "포천이동" 은 능선 너머 다른 중권역(영평천)이다. 백운계곡도 광덕산 AWS(3.1 km, 1,050 m)가 화천 쪽 중권역이라 제외된다.

**재설계 후보**(사용자 결정 사항, 이 문서는 데이터만):
- (a) 부분 노출: 상류 관측소가 실제로 있는 3~4개 계곡만 배지, 나머지는 숨김(valley-ds 40~70% 대응 그대로).
- (b) 점 관측소 대신 **격자 강수**로 전환 — 기상청 초단기실황/초단기예측(1 km 격자)·레이더 강수 합성장을 계곡 유역 폴리곤(R2)에 평균해 "유역 강수" 를 만든다. 관측소 위치 문제가 사라지고 30/30 에 값이 생긴다. 검증은 별도 항목.
- (c) 유역 조건을 완화해 **능선 너머 고지 관측소**(광덕산·포천이동 등)를 "인접 산지 강우" 로 쓴다 — 표고 조건만 유지하면 19/30(63%). 물리적으로는 다른 유역이라 경보의 의미가 약해진다.
- (d) 광역 특보(기상청 호우특보 시군 단위) 중계로 축소(valley-ds <40% 대응).

## 실행

```sh
pnpm research:coverage              # 캐시(.cache/) 재사용, valleys.json 있으면 재검색 안 함
pnpm research:coverage --regeocode  # 계곡 좌표를 VWorld 검색으로 다시 뽑아 valleys.json 갱신
```

키는 저장소 루트 `.env.local` 의 `HRFCO_API_KEY` · `KMA_APIHUB_KEY` · `VWORLD_API_KEY`(`env.ts` 가 dotenv 없이 읽고, 오류 메시지에서도 가린다).
첫 실행은 VWorld WFS 점 질의 ~250건(150 ms 간격)으로 1~2분, 이후는 캐시로 수 초.

## 한계

- **좌표 정확도** — 계곡은 선인데 점 하나(VWorld 검색 결과)로 대표한다. 골짜기 지명 점(18개)은 골짜기 중간쯤, 휴양림·관광지·유원지·펜션(10개)은 **계곡 입구**라 표고가 낮게 잡혀 표고 조건이 느슨해진다(커버리지가 과대 평가되는 쪽). 산정호수는 호수 점(비선폭포 계곡의 하류). 수기 2개는 대략 좌표.
- **중권역 기준의 거칠음** — 중권역(1013 가평천, 1022 한탄강 등)은 수백 km² 라 "같은 중권역" 은 "같은 큰 강 유역" 정도의 뜻이다. 같은 중권역이라도 다른 골짜기(용추계곡 ↔ 화악교, 소요산 ↔ 연천 관측소)를 상류로 셀 수 있다 → 역시 과대 평가. 반대로 능선 바로 너머 고지 관측소(백운 ↔ 광덕산 3.1 km)는 제외된다. 표준유역(sbsncd) 일치 열을 병기했다(7/30).
- **표고 소스** — Terrarium z12 는 ≈30 m 격자(SRTM 계열 혼합)라 골 바닥 점이 사면 값으로 잡힐 수 있다(±20~40 m). 관측소 제원 표고(AWS 노장 해발·수위 영점표고)와 기준면이 미세하게 다르다. 표고차 1~30 m 의 매칭은 신뢰하지 않는 게 맞다(엄격 열 참고).
- **표고 ≥ 는 상류의 필요조건일 뿐** — 높다고 물이 계곡으로 오는 건 아니다. 진짜 상류 판정은 R2 의 유역 폴리곤(또는 DEM 유역 추적)으로 "계곡 점의 상류 집수역 안" 을 봐야 한다. 이 실측은 그 전 단계의 느슨한 상한이다 — **느슨한 상한이 40% 라는 것이 결론이다.**
- HRFCO 제원 좌표 표기 오류(초 ≥ 60, 예 `37-20-91`) 는 `suspicious` 로 표시만 하고 그대로 계산했다(수도권 안에서 매칭에 걸린 건 없음).
- 표본 30개는 수기 선정(가평 9·포천 4·남양주 3·양주 2·동두천 2·양평 2·연천·파주·의정부·서울·인천·춘천·화천 각 1). 가평 북면 비중이 커서 가평천 상류의 0 이 결과를 끌어내린다 — 실제 서비스 대상 분포와 비슷하다고 본다.
