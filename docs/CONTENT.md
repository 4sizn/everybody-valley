# 홈 콘텐츠 운영

홈은 주간 안내·명소·광고 배너, 최근 7일 관심 계곡, 블로그 방문기로 구성한다. 계곡 찾기는 기존 검색·필터·전체 목록을 제공한다. 같은 블로그 카드가 계곡 미리보기와 지도 시트의 **방문 후기** 탭에도 표시된다.

## 등록 순서

1. 서버 환경에 `ADMIN_TOKEN`을 설정하고 재시작한다. 토큰을 웹 빌드 환경이나 Git에 넣지 않는다.
2. 앱 **설정 → 서비스 운영자 관리 → 인증 → 홈 콘텐츠 → 배너·블로그 등록**을 연다.
3. 종류와 연결 계곡, 제목, 소개, 작성자·광고주, HTTPS 원문 링크, HTTPS 이미지 주소와 출처·권리자, 원문 작성일을 입력한다.
4. 노출 시작·종료일과 공개 여부를 정한다. 광고·협찬은 해당 체크를 켠다. 저장 후 홈과 해당 계곡에서 확인한다.

신규 콘텐츠는 기본 비공개다. 공개를 켜도 한국 시간의 게시 기간 밖이면 노출하지 않는다. 시작일·종료일 당일은 포함한다. 최신 수정 순으로 표시하며 배너가 여러 개면 손가락으로 좌우로 넘긴다(번호 버튼은 없앴다). 6초마다 다음 배너로 자동 넘어가고, 사용자가 한 번이라도 직접 넘기면 그 뒤로는 자동 넘김을 멈춘다. 화면이 뒤에 있거나 기기에서 동작 줄이기를 켰으면 자동으로 넘기지 않는다. 홈 히어로는 사진이 주인공이라 소개문을 세 줄에서 자른다 — 배너 소개는 150자 안쪽으로 쓴다. 저장한 페이지는 즉시, 다른 열린 페이지는 포커스 복귀 또는 최대 60초 간격으로 갱신한다.

일반 배너는 원문 링크를 비우면 연결 계곡 미리보기를 연다. 링크가 있으면 새 탭에서 원문을 연다. 블로그와 광고 배너는 링크가 필수다. 광고 배너에는 광고주와 광고 표시, 광고 블로그에는 광고 배지를 붙인다.

이미지는 직접 업로드·수집하지 않고 등록된 주소에서 표시한다. 게시 권한을 확보한 안정적인 이미지 주소를 사용한다. 원문 사이트가 외부 이미지 표시를 막거나 이미지를 삭제하면 이미지 준비 중으로 표시하며 글과 링크는 유지한다. 임의 예시 글·사진·순위를 운영 데이터로 채우지 않는다.

수정에서 비공개로 전환하거나 기간을 바꿀 수 있다. 삭제는 확인 버튼을 한 번 더 눌러야 한다. 전체 보관 한도는 배너와 블로그 합계 200개다. 제목 100자, 소개 300자, 작성자 80자, 이미지 출처 160자, URL 2,000자 제한이며 서버도 검증한다.

## 초기 자료 채우기

빈 홈을 공개 출처로 한 번에 채울 때는 `pnpm seed:discovery` 를 쓴다. 계곡별 배너를 모아 운영자 API 로 등록하며, 등록한 뒤에는 어드민에서 여느 콘텐츠처럼 고치거나 비공개로 바꾼다.

- 출처는 재게시 권한이 분명한 둘뿐이다. **TourAPI**(한국관광공사, 공공누리 제1유형)는 `.env.local` 의 `DATA_GO_KR_KEY_ENCODING` 이 있어야 하고 data.go.kr 에서 "국문 관광정보 서비스_GW" 활용신청이 필요하다. **Wikimedia Commons** 는 키가 없어도 되지만 계곡 사진이 드물어 2026-09-17 실측 33곳 중 3곳만 맞았다.
- 임의 블로그·검색 결과는 긁지 않는다. 블로그 카드는 운영자가 원문 링크를 직접 등록한다.
- 기본은 수집 결과만 표로 보여준다. 확인한 뒤 `--apply` 를 붙여 등록한다. 사진 주소가 열리지 않는 계곡은 등록하지 않는다.
- 등록되는 소개문은 150자에서 자른다. 홈 히어로에서 세 줄까지만 보이기 때문이다.

## 주간 관심 순위

- 한국 시간 오늘과 이전 6일, 총 7개 날짜를 합산한다. 실제 방문 인증이나 고유 이용자 수가 아닌 **계곡 지도 선택 횟수**다.
- 미리보기만 여는 경우에는 집계하지 않는다. 큰 지도 선택과 선택된 계곡 직접 링크 진입은 집계한다. 같은 접속 IP의 같은 계곡은 하루 한 번만 반영한다.
- 수가 같은 계곡은 공동 순위(1, 1, 3)를 표시한다. 최대 5개이며 경계 동률은 계곡 ID 순으로 결정한다.
- 순위 테이블에는 원본 IP 대신 서버 비밀키와 날짜를 포함한 HMAC을 저장한다. DB의 비밀키는 재시작 후에도 유지한다. 최근 7일 밖 기록은 공개 피드 조회나 관심 선택 요청 때 삭제한다.
- 공유 Wi-Fi/NAT는 합쳐지고, IP가 달라지면 별도로 집계될 수 있다. 로그인·방문 인증을 대신하지 않는다. 기존 API 요청 제한을 적용한다.
- 프록시 뒤에서는 [운영 문서](PRODUCTION.md)의 `TRUST_PROXY` 조건을 지켜야 한다. 신뢰할 수 있는 프록시에서 전달 헤더를 덮어쓰지 않으면 집계/요청 제한을 조작할 수 있다.

집계가 없으면 순위를 만들지 않고 계곡 둘러보기를 안내한다. 블로그가 없으면 준비 중 상태, 특정 계곡에서는 외부 블로그 검색 링크를 제공한다. API 오류는 재시도 버튼으로 구분한다.

## 저장·API

마이그레이션 `0006_discovery.sql`이 기존 DB에 콘텐츠·관심 집계·집계 비밀키 테이블을 추가한다. 기존 제보/관측 테이블을 바꾸지 않는다. 콘텐츠는 기존 SQLite 영속 볼륨·백업에 포함된다.

- `GET /api/discovery`: 공개 중인 콘텐츠, 최근 7일 순위, 집계 기간. 캐시하지 않는다.
- `POST /api/discovery/interest/:valleyId`: 알려진 계곡 선택 집계, 성공 204.
- `GET/POST /api/admin/discovery`: 운영자 목록/신규·수정. 기존 Bearer 인증과 운영자 요청 제한을 적용한다.
- `DELETE /api/admin/discovery/:id`: 운영자 삭제. `ADMIN_TOKEN` 미설정이면 운영자 API는 404다.

글 본문은 복제하지 않고 운영자가 쓴 소개와 원문 링크만 제공한다. 광고 판매·결제, 자동 블로그 수집, 실제 방문 인증은 포함하지 않는다.
