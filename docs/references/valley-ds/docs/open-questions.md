## 🔴 계획에 실려 있는 검증 안 된 가정

계획의 킬러 기능 두 개가 아직 검증 안 된 가정 위에 서 있습니다.
**둘 다 이번 주에 판정하세요.** 구현 3주 차에 알면 늦습니다.

### A. 상류 강우 경보 — 관측소가 계곡 상류에 있는가

- [ ] 기상청 AWS(방재기상관측) 관측소 목록 확보 (좌표 + 표고)
- [ ] 한강홍수통제소 수위/우량 관측소 목록 확보
- [ ] 후보 계곡 30개와 매칭: 같은 유역 + 표고 더 높음 + 거리 N km 이내
- [ ] **커버리지 집계** — 몇 개 계곡이 쓸만한 상류 관측소를 갖는가

**판단 기준**

| 결과 | 대응 |
|---|---|
| 70% 이상 | 계획대로 진행 |
| 40~70% | 커버되는 계곡만 경보 배지 노출, 나머지는 기능 숨김 |
| 40% 미만 | **MVP를 주차·혼잡 중심으로 재설계.** 경보는 광역 특보 중계로 축소 |

**조사 중 나온 수정 사항**: 강우는 **기상청 AWS가 홍수통제소보다 촘촘**합니다.
"상류 강우 = AWS", "수위 = 홍수통제소"로 소스를 나누세요.

- 기상청 API허브 https://apihub.kma.go.kr/
- 방재기상관측(AWS) https://data.kma.go.kr/data/grnd/selectAwsRltmList.do
- 한강홍수통제소 https://www.hrfco.go.kr/web/openapiPage/openApi.do

### B. 그늘 지도 — 현재 계획대로는 어렵습니다

두 가지 문제:

1. 확인된 무료 DEM은 **90m 격자**. 계곡 폭이 20~50m라 골짜기 자체가 뭉개집니다
2. 더 큰 문제 — **계곡 그늘의 대부분은 나무 그늘**인데 DEM은 지반고라 수목이 안 잡힙니다.
   수목을 보려면 DSM/항공LiDAR가 필요하고 난이도가 다른 얘기입니다

- [ ] 국토지리정보원 5m급 DEM 신청 절차·비용·라이선스 확인
- [ ] DSM 또는 수목높이 데이터 존재 여부 확인
- [ ] 90m DEM으로 후보 계곡 1개 시험 계산 → 그림자가 의미 있게 나오는지 눈으로 확인

**권장 대안 (지금 기준 이쪽이 현실적)**
지형 시뮬레이션을 빼고, 정사영상으로 나무 밀도를 보고 **구간별 그늘 태그를 수기 입력**
(`오전 그늘 / 오후 그늘 / 종일 그늘 / 그늘 적음`). 사용자 체감은 거의 같고 비용은 1/20입니다.
DEM은 **접근 경사도** 산출에만 쓰면 90m로도 충분합니다.

공공데이터포털 API는 자동승인과 **심의 대상**이 섞여 있습니다. 심의면 며칠 걸립니다.

- [ ] 한강홍수통제소

- [ ] TAGO 대중교통

## 🟡 유역 데이터 확보 경로

상류 관측소 자동 매핑의 전제입니다. VWorld WFS는 WMS보다 제공 레이어가 적어서,
유역이 **래스터로만** 오면 point-in-polygon이 안 됩니다.

- [ ] VWorld에서 표준유역/권역을 **벡터(WFS)** 로 받을 수 있는지 확인
- [ ] 안 되면 → 국토교통부 표준권역 API 확인 https://www.data.go.kr/data/15056790/openapi.do
- [ ] 안 되면 → WAMIS 유역도 shapefile 다운로드 http://wamis.go.kr/wsc/wsc_basinbnd_lst.do
- [ ] 확보한 유역 폴리곤으로 계곡 좌표 point-in-polygon 1건 성공시키기

**어느 경로든 결과는 같습니다**: 유역 폴리곤을 한 번 받아서 우리 쪽에 저장하고,
계곡 등록 시점에 유역 코드를 박아둡니다. 런타임에 VWorld를 부르지 않습니다.

## 🟡 결정 사항 — 조사가 아니라 선택

### 위치정보 스탠스 (아키텍처를 가릅니다)

개인위치정보를 **서버에 저장**하면 위치정보사업 신고 대상이 될 수 있습니다.
"계곡 반경 진입 시 자동 경보" 같은 서버 지오펜스를 하려면 저장이 필요합니다.

- [ ] 결정: **구독형** (사용자가 계곡을 구독 → 경보 발송, 서버는 위치를 모름)
- [ ] 또는: **지오펜스형** (위치 저장 + 신고 절차 확인 필요)

> 권장은 구독형입니다. 위치는 클라이언트에서만 쓰고(내 위치 표시·거리 계산)
> 서버엔 남기지 않으면 설계가 훨씬 단순해집니다.
> 실제 신고 의무 여부는 법률 전문가·소관 기관 확인이 필요합니다 — 이 문서는 법률 자문이 아닙니다.

### 푸시 전달 경로

- [ ] 결정: 웹푸시 / 카카오 알림톡 / 문자 / 조합

> iOS Safari 웹푸시는 **홈 화면 추가(PWA)를 해야만** 옵니다. 계곡 앱을 홈에 추가하는
> 사용자는 거의 없습니다. 안전 경보를 웹푸시에만 걸면 iOS 사용자는 사실상 못 받습니다.

### 베이스맵

- [ ] 결정: 자체 OpenMapTiles 호스팅 / 외부 무료 호스팅으로 시작

> 자체 호스팅은 planetiler → 한국 추출 → mbtiles/pmtiles → 호스팅. 시간·비용 견적 필요.
> 외부로 시작하면 **스타일 커스터마이즈 자유도가 달라져서** 나중에 바꿀 때 색을 다시 잡아야 합니다.
> 1주 차에 결정하세요.

### 성능 예산

- [ ] 초기 JS 예산: ______ KB (제안: 500KB — spotts는 1.68MB지만 그건 도심 기준)
- [ ] LCP 목표: ______ (제안: 3G에서 2.5s)
- [ ] 오프라인 범위: 마지막 위치 + 주변 시설 캐시까지? 타일 프리캐시까지?

> 계곡은 산속이라 LTE가 약합니다. 예산을 먼저 못 박고 시작하세요.

### 면책 고지

- [ ] 안전 경보 관련 면책 문구 확정
- [ ] 데이터 출처 표기 위치 확정

> spotts에도 "공식으로 제공하는 정보가 아닙니다. 사용에 주의..." 문구가 있습니다.
> 안전 경보를 내는 앱은 이게 선택이 아닙니다.

## 🟢 싸게 끝나는 빠진 조사

- [ ] **경쟁 조사** (30분) — 네이버·카카오 지도에 계곡 정보가 이미 얼마나 있는지,
      기존 계곡 앱이 왜 죽었는지
- [ ] **계곡 시드 목록 출처** (1시간) — "전국 계곡 목록" 공식 데이터셋이 있는지.
      없으면 하천망에서 자르거나 수기
- [ ] **콘텐츠 시딩 비용 산정** — 계곡 30개 × 구간 3개 = 90개의 수심·바닥재·그늘을
      누가 어떻게 채우나. spotts는 vault 기반 수작업 큐레이션이었습니다
- [ ] **VWorld 상업적 이용 조건** (30분) — 정사영상·지적도 재배포 제한 여부
