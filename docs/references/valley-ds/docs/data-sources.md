## 1. VWorld

엔드포인트: `http://api.vworld.kr/req/{wms|wfs|data|address|search}`

| 레이어/API | 계곡 앱에서의 쓸모 | 우선순위 |
|---|---|---|
| **하천망 + 표준유역** (WMS/WFS) | 계곡을 LineString으로 자동 시딩. **계곡↔상류 관측소 자동 매핑** | ★★★ |
| **지적도** `lp_pa_cbnd_bubun` | 하천구역·국유지 경계 → 평상·자릿세 이슈 시각화 | ★★ |
| **용도지역 / 도시계획** | 개발제한·자연환경보전 → 야영·취사 가능 여부 | ★★ |
| **항공·정사영상** (WMS raster) | 위성 토글. 수면 폭·나무 그늘·갓길 주차 공간 확인 | ★★ |
| **Geocoder 2.0** (주소↔좌표) | 주소 없는 계곡 지점의 역지오코딩 → 119 좌표 카드 | ★★★ |
| **검색 API** | 지명·POI 검색 보조 | ★ |
| **좌표변환** | 지자체 데이터 EPSG:5179/5186 → 4326 정규화 | ★★ |

문서: [WMS/WFS 2.0](https://www.vworld.kr/dev/v4dv_wmsguide2_s001.do) ·
[Geocoder 2.0](https://www.vworld.kr/dev/v4dv_geocoderguide2_s001.do) ·
[공공데이터포털 지오코더 API](https://www.data.go.kr/data/15101106/openapi.do)

**주의**

- 인증키는 **도메인 고정**. 브라우저에서 직접 부르면 키 노출 + 도메인 제한에 걸림
  → `/api/vworld/*` 서버 프록시 필수 (WMS 타일도 CORS 때문에 프록시 필요)
- WFS는 WMS보다 제공 레이어가 적습니다. 벡터로 필요한 건 한 번 받아 **자체 타일로 굽고**,
  나머지는 WMS 래스터로
- 상업적 이용 조건·트래픽 한도 확인

## 2. 안전 — 이 앱의 존재 이유

| 데이터 | 기능 | 링크 |
|---|---|---|
| 행안부 **생활안전지도 물놀이관리지역** | 공식 위험구역 폴리곤을 지도에. spotts 통제구역 레이어 구조 재사용 | [data.go.kr/15101866](https://www.data.go.kr/data/15101866/openapi.do) |
| 행안부 **생활안전지도 산사태위험지도** | 호우 시 대피 판단. 계곡 = 산비탈 아래 | [data.go.kr/15149602](https://www.data.go.kr/data/15149602/openapi.do) |
| 산림청 **과거산사태 정보** | 이력 있는 계곡 표시 | [data.go.kr/15074816](https://www.data.go.kr/data/15074816/openapi.do) |
| 행안부 **장소별 물놀이 안전사고 통계** | 사고 유형을 계곡 상세 경고 문구로 | [data.go.kr/15107188](https://www.data.go.kr/data/15107188/openapi.do) |
| **한강홍수통제소** 실시간 수위·강우 | 상류 경보의 심장. 10분 단위 | [hrfco.go.kr OpenAPI](https://www.hrfco.go.kr/web/openapiPage/openApi.do) |
| **기상청** 초단기실황·특보 | 소나기·호우주의보 푸시 | [기상자료개방포털](https://data.kma.go.kr/) |

### 상류 경보 설계 메모

```
1. 계곡 좌표 → VWorld 표준유역 폴리곤 point-in-polygon → 유역 코드
2. 유역 내 + 표고가 더 높은 관측소를 상류 후보로 선정
3. 후보별 10분 강우 / 수위 변화율을 폴링 (서버에서, 캐시)
4. 임계 초과 시 해당 계곡 구독자에게 푸시 + SSE 채널로 지도 배너
5. 경보 이력을 저장해 사후 검증 → 임계값 튜닝
```

임계값은 **보수적으로**. 오경보 몇 번이 미경보 한 번보다 낫습니다.

## 6. 지형 — API가 아니라 파일

DEM은 OpenAPI가 아니라 **다운로드 데이터셋**입니다. 런타임 호출이 아니라 빌드 타임에 굽습니다.

| 자산 | 출처 |
|---|---|
| 국토지리정보원 **DEM** | [data.go.kr/15059920](https://www.data.go.kr/data/15059920/fileData.do) |
| **수치표고모델 90M** | [NSDI 오픈마켓](http://data.nsdi.go.kr/dataset/20001) |
| 국토정보플랫폼 오픈API | [map.ngii.go.kr](https://map.ngii.go.kr/mi/openKey/openKeyInfo.do) |

### DEM으로 굽는 것 3가지

1. **시간대별 그늘 폴리곤** — 태양 고도(SunCalc) × 지형 → 계곡당 1시간 간격 12장 GeoJSON
2. **접근 경사도** — 주차장→물가 경로의 평균/최대 경사 → 난이도 등급
3. **물길 방향** — 상류/하류 자동 판정 (구간 순서 자동 생성)

## 7. 공통 실무 규칙

### 좌표계

정부·지자체 데이터는 EPSG:**5179**(UTM-K), **5186**(중부원점), **4326**이 섞여 옵니다.

> **저장 시점에 전부 4326 `[lng, lat]`으로 정규화하세요.**
> spotts가 런타임 좌표 변환 코드를 아예 안 두는 이유입니다. 런타임에 변환하면
> 표현식·거리 계산·클릭 판정이 전부 오염됩니다.

### 호출 구조

```
정부 API ──(서버에서 폴링 + 캐시)──> 우리 DB/KV
                                      │
                        ┌─────────────┴─────────────┐
                   REST (초기 로드)            SSE (실시간 갱신)
                        └─────────────┬─────────────┘
                                   클라이언트
```

- 실시간 계열은 일일 호출 한도가 있습니다. **클라이언트가 정부 API를 직접 부르지 않게** 하세요
- spotts가 따릉이를 `/api/seoul-bike/positions`로 감싸고 `/api/events?channel=bike` SSE로
  갱신하는 구조가 그대로 정답입니다

### 데이터셋 메타데이터

spotts처럼 GeoJSON 파일마다 출처를 박아두세요. 나중에 재생성할 때 살아납니다.

```json
{
  "$schema": "./.schema/valleys.schema.json",
  "type": "FeatureCollection",
  "metadata": {
    "description": "수도권 계곡 구간 카탈로그",
    "source": "VWorld 하천망 + 현장 검수",
    "sourceFile": "~/vault/valley/data/metro-valleys.geojson",
    "datasetVersion": "2026-09-01.1",
    "collectedAt": "2026-09-01",
    "coordinateOrder": "[longitude, latitude]"
  },
  "features": []
}
```

### 출처 URL 화이트리스트

spotts의 research-links 파일에 이런 메모가 있습니다.

> "여기에 URL을 적는 것은 우리 서버가 그 주소를 호출해도 된다는 선언 —
> OG 미리보기의 허용 호스트가 이 파일에서 파생된다."

외부 링크 미리보기를 만들 거면 **데이터 파일에서 허용 호스트를 도출**하세요. SSRF 방어가 공짜로 됩니다.

## 8. 착수 순서

1. VWorld 키 발급 → `/api/vworld/*` 프록시 뼈대
2. 표준유역 폴리곤 받아서 수도권 계곡 30개 좌표와 point-in-polygon 매칭
3. 한강홍수통제소 관측소 목록 → 유역별 상류 후보 선정 스크립트
4. 여기까지 되면 **상류 경보의 데이터 파이프라인이 검증**된 것 — 그다음 UI
