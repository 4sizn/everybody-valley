# modu-valley — 작업 규칙

## 시각 증명 없이 완료 선언하지 않는다 (사용자 규칙, 2026-09-07)

사용자 가시 결과물이 있는 작업은 코드·테스트·빌드 통과만으로 끝나지 않는다. `visual-e2e-proof`
스킬의 완료 게이트를 따른다 — **실제 사용자 표면에서 캡처 → 이미지를 직접 열어 검증 → 채팅에
절대경로 인라인 표시 → OS 미리보기로 열기**. 넷 중 하나라도 빠지면 미완료다.

**하위 워크트리도 같다.** 워크트리 에이전트는 증명 이미지를 GitHub 브랜치 링크로만 남기지 말고
**메인 저장소의 `/Users/hsshin/Documents/lotus/modu-valley/.proof/<항목>/` 에 PNG 로 저장**(워크트리 안의 `.proof/` 가 아니다 — 워크트리를 지우면 사라진다. 절대경로를 그대로 쓴다)하고 절대경로를 PR 본문에 적는다. 그 디렉터리는
gitignore 대상이고 **워크트리를 지워도 남는 공유 위치**라 메인 세션이 그대로 열어 사용자에게
보여줄 수 있다. 링크는 인라인 표시도 미리보기도 되지 않는다.

**저장 뒤 반드시 선별 검사를 돌린다** — `python3 scripts/proof-check.py .proof/<항목>` (표준
라이브러리만 쓴다). 단색·로딩 화면을 `FAIL` 로 잡는다. `FAIL`·`WARN` 이 하나라도 있으면 다시
찍는다. **`OK` 는 "내용이 맞다" 는 뜻이 아니다** — 사람이 이미지를 여는 단계를 대체하지 않는다.
검사기는 대조 표본(순수 단색·스피너만 있는 로딩 화면)으로 실제로 잡히는지 확인해 두었다.

**캡처는 웹 브라우저에서, 모바일 크기 기준으로 한다**(사용자 결정 2026-09-07).
android/ios 실기기·시뮬레이터 검증은 **빌드가 느려 나중에 한다** — 지금은 요구하지 않는다.

**반응형 뷰포트** — 이 앱의 폭 분기점은 **592px 하나**다(`CenterColumn`:
`columnWidth = min(SIZES.column 560, width − gutter 32)`, `isNarrow = columnWidth < 560`
→ `width < 592` 면 narrow). 그래서 임의의 기기 크기보다 **경계 양쪽**에서 찍는 것이 중요하다.

| 뷰포트 | 왜 |
| --- | --- |
| **390×844** | 기준 폰. **모든 상태를 라이트·다크 둘 다** 여기서 찍는다 |
| 360×740 | 좁은 안드로이드 하한 — 잘림·겹침이 여기서 먼저 난다 |
| **591×844 / 592×844** | `isNarrow` **경계 쌍**. 대표 상태 하나를 두 폭에서 나란히 |
| 1440×757 | `docs/PARITY.md` 기준 뷰포트 — `/firework` 픽셀 diff 는 **반드시 이 크기** |

360 과 경계 쌍·1440 은 **대표 상태 하나**만으로 충분하다(모든 상태를 다 찍지 않는다).

캡처는 실행 중인 Expo web 화면에서 한다 — 컴포넌트 단독 렌더나 테스트
출력으로 대체하지 않는다. 빈 화면·로딩 중·오래된 캐시가 찍혔으면 다시 찍는다(지도가 빈 화면으로
렌더되는 Metro 열화 함정이 있다 — 새 서버·새 브라우저로 첫 캡처).

## 개인위치정보는 기기를 떠나지 않는다 (사용자 규칙, 2026-09-07)

사용자의 위치정보를 **서버로 보내지 않는다.** 내 위치는 기기 안에서만 쓴다 — 지도를 옮기고,
화면에 좌표를 띄우는 데까지다. 서버 요청의 파라미터로도, 로그로도, 저장으로도 나가지 않는다.

**왜** — 위치정보법상 **위치기반서비스사업 신고는 개인위치정보를 취급할 때 발생한다**(방통위
산하 위치정보지원센터 안내). 신고 주체는 사업자이고(정부24 — 개인사업자 포함), 소상공인·1인
창조기업 특례도 확인서류가 필요해 결국 사업자등록이 전제다. 개인위치정보를 다루지 않으면
**신고 대상이 아니다** — 지금 구조를 유지하는 것이 규제 비용을 0 으로 두는 방법이다.

**어떻게 지키나**
- 좌표로 외부 API 를 부를 때는 **계곡 좌표**(고정 데이터)를 쓴다. 사용자 GPS 를 쓰지 않는다.
  예: N2 근접 정류소 조회는 계곡 좌표 기준이다 — 기능상으로도 그게 맞다(사용자는 그 계곡을
  보고 있고, 자기 위치에서 막차를 재는 것이 아니다).
- 119 좌표 카드(N3)처럼 내 위치를 **보여주는** 것은 된다. 그 좌표를 서버에 남기면 안 된다.
- "내 근처 계곡 정렬" 처럼 서버가 사용자 위치를 알아야 하는 기능은 이 선을 넘는다 — 만들기
  전에 사용자에게 묻는다. 정식 서비스로 낼 단계에서는 변호사 검토가 필요하다.

## `/firework` 결과물 보존 (사용자 규칙, 2026-09-03)

`/firework` 라우트(불꽃축제 데모)의 작업 결과물은 **보존 대상**이다. 기준은
커밋 `8db5be31` (PR #1, "불꽃축제 지도 데모를 Expo web 으로 전환") 이후의 결과다.

- `/firework` 에서 **보이는 것과 동작**을 바꾸는 수정은 하지 않는다 — 밤하늘,
  3D 건물, 명당 레이어, 티커, 카메라 순회, 시트 배치, 컨트롤. `docs/PARITY.md` 의
  측정표가 그 계약이다.
- 공유 코드(`map-style`·어댑터·셸 컴포넌트·토큰)를 고칠 때는 `/firework` 가
  **같게 보이는지**를 먼저 확인한다. 다크 테마를 강제(`EXPO_PUBLIC_THEME=dark`)해
  main 과 나란히 스크린샷을 비교하고 PR 에 남긴다.
- 테마가 라이트여도 `/firework` 의 구성 요소(3D 건물 등)가 **사라지면 안 된다**.
  색은 팔레트를 따르되 요소는 유지한다.
- 계곡 화면이 `/firework` 의 어떤 부분과 **같은 것을 필요로 하면, 공유하지 말고 클론한다**
  (사용자 규칙, 2026-09-07 — 티커 사례). festival 컴포넌트를 계곡 요구로 고치는 것은
  그 자체로 금지다. 계곡 전용 사본을 새로 만들고(`components/valley/*`), 이후 변경은
  사본에서만 한다. 장면 분기(`scene === 'festival'`)도 그대로 둔다. 코드 중복보다
  원본 보존이 우선이다.
- 리팩터로 내부 경로가 바뀌는 것은 허용된다(예: 스타일을 URL 대신 객체로 생성).
  결과가 같아야 한다.
- 계곡 화면(`/`)의 요구 때문에 `/firework` 를 희생시켜야 할 것 같으면 고치지 말고
  사용자에게 묻는다.
